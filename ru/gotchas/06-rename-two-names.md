# RENAME с двумя именами не работает

> Формы RENAME /СТАРОЕ /НОВОЕ нет. Встаньте на элемент, затем NAME /НОВОЕ. Массовое переименование — по =ref.

**E3D пишет:** `(2,109) Undefined name`

**Команды:** `RENAME` **Проверено** · `NAME` **Проверено**

## Что вы видите

```
RENAME /PMLC-CWAY-T3 /PMLC-CWAY-T5
(2,109) Undefined name /PMLC-CWAY-T5
```

«Крышечки» стоят на втором имени. В некоторых списках команд эта форма с двумя аргументами есть — она неверна.

## Почему

`RENAME` (как и `NAME`) переименовывает **текущий** элемент. Второе слово читается как адрес, куда перейти, а элемента с новым именем ещё нет.

## Как правильно

По две строки на элемент: перейти к нему, затем дать новое имя. Массово переименовывайте по стабильному адресу — номера и имена сдвигаются, а `=ref` нет:

```
=12345678/6304
NAME /PMLC-CWAY-T5
```

Занятое имя отклоняется (`Name … already used`), и ничего не меняется. Если меняете имена местами, сначала переименуйте через временный префикс.

## Проверьте сами

На тестовом элементе, под меткой:

```
MARKDB |rename probe|
NAME /BPML-RENAME-PROBE
Q NAME
UNDODB
Q NAME
```
